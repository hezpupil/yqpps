# 友趣 App 短剧源接入 + 模块机制移植方案

日期：2026-11-23　｜　状态：修订版（用户要求：直接用 guoapp 的源 + 移植模块化）

---

## 〇、对上一版方案的纠正

上一版我判断「guoapp 商店没有可直接用的新短剧源」——**这个结论是错的，现纠正**。

把 `guoapp-modules/hongguo` v1.0.7 的源码逐行核实后：

- 它是一个**现成的、非成人（`adult: false`）、持续更新（1.0.0→1.0.7）**&#x7684;短剧数据源，涵盖短剧/漫剧/AI 剧/听书。
- 它**不依赖 Node 专有 API**（无 `require` / `Buffer` / `process` / `TextEncoder`），151KB 纯 JS，理论上可在任何合规 JS 引擎里运行。
- 上游域名是**字节系**（`hongguoduanju.com`、`api5-normal-sinfonline{a,b}.fqnovel.com`），与我们现用的 hezi1 `/java/drama/*` 完全是两套接口——这才是真正的「换一个数据源」。
- 私有签名算法（SM3、签名 V5、AES-CBC、protobuf 手工编码）**全部写在模块 JS 内部**，我们不需要逆向，引擎执行即可。

所以你的判断成立：**源可以直接用**。真正的工作不是「写新源适配器」，而是「把能跑这个模块的宿主环境移植过来」。

## 一、结论先行

| 问题                                | 结论                                                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 能直接用 guoapp 的源吗？                  | **能**。红果模块的 JS 可直接执行；数据、搜索、榜单、弹幕、分季、媒体解析全在模块内                                                                  |
| 直接挂到我们 App 上就能跑吗？                 | **不能**。它需要 31 个宿主 API（`host.fetch` / `md5` / `sm3` 相关字节操作 / `cache` / `parseHtml` 等）和配套网络栈；缺一个就报错              |
| 「想装就装想删就删」能做到吗？                   | **能，且比自己发明机制更好**：直接移植 guoapp 已验证的模块协议（manifest + main.js + zip + 索引 + sha256）                                  |
| 推荐路线                              | **移植 guoapp 的 Go 核心到两端**（Android `.so` + iOS `.xcframework`），Dart UI 换成我们现有 Kotlin/Swift UI；模块协议、JS 引擎、网络栈原样复用 |
| 为什么不自己用 Kotlin/Swift 重写 host API？ | 31 个 API + goja 同步语义 + 字节签名所需的字节操作，双端各写一遍成本高于直接编译 Go 核心；且以后每次模块升级都可能要补 API                                     |
| 最大风险                              | ① Go 核心接入双端 CI 与包体；② 字节系域名是否也拦我们的服务器出口/OkHttp（需实测）；③ iOS 静态库签名与审核                                              |

## 三、guoapp 运行时结构（要移植的东西）

| 层     | 文件/规模                                                                   | 作用                                              |
| ----- | ----------------------------------------------------------------------- | ----------------------------------------------- |
| JS 引擎 | `goja`（Go 依赖）                                                           | 同步执行 CommonJS 模块                                |
| 模块加载  | `native/core/module_loader.go`（270 行）                                   | 读 manifest、编译 main.js、能力接口断言、id 唯一性             |
| 模块宿主  | `native/core/module_script.go`（525 行）+ `module_host.go`（459 行）          | 31 个 host API 的实现与 goja 绑定                      |
| 网络栈   | `fhttp` + `tls-client`（`go.mod` 依赖）                                     | Chrome TLS 指纹伪装（这正好是我们被 WAF 拦的痛点）               |
| 媒体代理  | `app_stream.go` / `app_stream_cenc.go`                                  | 本机 HLS 改写、Range 透传、加密媒体                         |
| 业务层   | `app_catalog_cache.go` / `app_playback.go` / `app_sources.go` 等约 50 个文件 | catalogue、播放、追剧、下载等——**这部分我们不用**，UI 和数据层保留我们自己的 |
| 构建产物  | Android `c-shared` → `.so`；iOS `c-archive` → 静态库                        | 与 Flutter 通过 FFI 桥接，我们改成与 Kotlin/Swift 桥接       |

**核心判断**：真正需要移植的是「JS 引擎 + 模块加载 + 宿主 API + 网络栈 + 媒体代理」这一层，约 1,200 行核心代码 + 成熟第三方库；业务/UI 层全部不要。

## 四、三条路线对比

| 路线                  | 做法                                                                                                                   | 优点                                                                                     | 缺点                                                              | 结论    |
| ------------------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------- | ----- |
| **A. 移植 Go 核心（推荐）** | 把 guoapp 的 Go core 裁剪到「引擎+模块+宿主+网络+媒体代理」，编译成 Android AAR(`.so`) / iOS XCFramework(`.a`)，Kotlin/Swift 通过 JNI / C 桥接调用 | 模块协议 100% 兼容 guoapp，红果源可直接用；**自带 Chrome TLS 指纹，可能直接解决我们被 WAF 拦的问题**；以后 guoapp 生态的模块都能装 | CI 要加 Go 工具链；iOS 静态库要过签名/审核；包体增大（Go 运行时 + tls-client 约 10–20MB） | ✅ 推荐  |
| B. 原生重写宿主 API       | Android 用 QuickJS/Rhino，iOS 用 JavaScriptCore；Kotlin/Swift 实现 31 个 host API                                           | 不引入 Go，包体小                                                                             | 双端各写 31 个 API；goja 同步语义要自己造；字节签名涉及的字节操作易错；以后模块升级要补 API          | ⚠️ 备选 |
| C. 服务端跑 JS          | 在服务器用 Node/goja 跑模块，App 只拿结果                                                                                         | App 改动小                                                                                | **服务器出口已被上游 WAF 拦**（历史实证）；字节系也可能拦；违背 C 方案手机出口原则                 | ❌ 否   |

## 五、实施路径（按路线 A）

### 阶段 0：可行性验证（1–2 天，先做，避免白干）

1. 在 Windows 本地用 Go 编译 guoapp core 的最小子集，写一个命令行 harness：`go run moduletool <hongguo 模块目录> {"action":"catalog","source":"hongguo","page":1}`。
2. 验证能否拿到红果真实数据（列表/搜索/详情/播放地址）。**如果字节域名也拦我们出口，先解决网络，否则后面全白做**。
3. 同时验证 `tls-client` 的 Chrome 指纹是否足以通过（这正是 guoapp 能在国内跑红果的原因）。

### 阶段 1：Go 核心裁剪 + 双端编译（3–5 天）

1. fork/copy guoapp 的 `native/core` 到我们仓库 `native/core`（保留许可证与署名），删除 UI/追剧/下载等无关业务文件。
2. 保留：`module_loader.go` / `module_script.go` / `module_host.go` / `network_*` / `app_stream*` / 必要的 helpers。
3. 统一对外接口为一个 C ABI：`DuanjuRequest(json) -> json` / `DuanjuFree`（与 guoapp 相同），我们只调 4 类 action：`catalog` / `search` / `detail` / `media`。
4. CI：`android.yml` 加 Go 构建 `.so` 到 `app/src/main/jniLibs/{arm64-v8a,armeabi-v7a}`；`ios.yml` 加 `c-archive` → XCFramework，签名嵌入。
5. 本地先用 `scripts/build_android.py` / `build_ios.py` 产出的产物做验证，CI 产出才是交付物（遵守既有约定）。

### 阶段 2：模块管理 UI（2–3 天，双端）

按 guoapp 四 Tab 移植到我们 App 的「短剧 › 模块管理」页：

| Tab  | 功能                                                                       |
| ---- | ------------------------------------------------------------------------ |
| 已安装  | 模块列表、启用/停用开关、版本、更新、卸载（保留该源的历史记录）                                         |
| 在线仓库 | 读 `guoapp-modules/index/index.json`（raw + jsDelivr 兜底），逐个/批量安装，校验 sha256 |
| 内置   | 随包内置的红果模块，卸载后不再自动装回（`.bundled-removed.json` 机制）                          |
| 手动   | 选择本地 zip 或输入 URL 安装                                                      |

操作：`installModule(token)` / `modules()` / `moduleIndex()` / `removeModule(id)` / `setSourceEnabled(id, bool)`，全部经 C ABI 到 Go 核心。

### 阶段 3：数据层切换（2–3 天）

1. 定义统一模型（对齐现有 `DramaModels.kt` / `DramaSeriesAPI.swift`，避免改 UI）：`DramaItem` / `DramaPageResult` / `DramaDetailData` / `PlaySource`。
2. `DramaRepository` / `DramaSeriesAPI` 改为：从 Go 核心拿模块返回的 JSON → 映射到统一模型。
3. **保留现有 C 方案链路作为兜底源**：模块源不可用时自动回退 hezi1，用户可在设置里选默认源。
4. 媒体播放：模块 `resolveMedia` 返回的 m3u8 经 Go 核心本机代理改写（复用现有 `/dm3u8` 路由或替换之）。

### 阶段 4：回归与发版（1–2 天）

- 双端回归：短剧首页/搜索/详情/选集/竖屏全屏/播放；模块安装/卸载/切换。
- 版本 1.0.35+，CI 全绿后上传服务器，force 更新。

## 六、风险与对策

| 风险              | 说明                                | 对策                                                                             |
| --------------- | --------------------------------- | ------------------------------------------------------------------------------ |
| 字节域名也拦我们网络      | 服务器出口 + OkHttp 指纹历史上被 hezi1 拦过    | 阶段 0 先实测；路线 A 自带 Chrome TLS 指纹（tls-client），大概率能过；必要时走 WebView 通道               |
| Go 核心体积         | Go 运行时 + tls-client 编译后可能 10–20MB | 只裁剪必要文件；`-trimpath -ldflags="-s -w"`；必要时只做 arm64                               |
| iOS 审核          | 静态库 + 动态模块加载可能被质疑                 | 模块只读自身数据目录、域名白名单、无热更新可执行代码绕过审核的说明；必要时内置模块为主、在线仓库为辅                             |
| 模块源合规           | guoapp 仓库含成人模块                    | 只内置/展示 `adult: false` 的模块；手动安装提示风险                                             |
| Java/ObjC 桥接复杂度 | C ABI 同步调用、线程、生命周期                | 参考 guoapp `core_bridge.dart` 的 `Isolate.run` + JSON 编解码模式，Kotlin/Swift 用后台线程调用 |
| 许可证             | guoapp 是开源项目（仓库含 LICENSE）         | 保留原许可证与署名；fork 前确认其条款是否允许商用/闭源集成                                               |

## 七、需要你拍板

1. **是否确认走路线 A**（移植 Go 核心）？确认后我先做阶段 0 的可行性验证，把红果数据真跑出来再动手改 App。
2. **内置哪个源作为默认**？红果（新）还是保留 hezi1（现用）？我的建议：红果设为默认，hezi1 保留为兜底可切换。
3. **是否接受包体增大**？路线 A 预计 +10–20MB。
4. 成人模块的处理：只展示 `adult: false`（我的建议），还是完全开放由用户自担风险？
